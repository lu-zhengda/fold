Fold is a local clipboard manager for macOS 26 and 27. It runs in the menu bar and opens a split view with clipboard history on the left and a preview on the right. Clipboard history stays on your Mac. Update checks contact GitHub.

## Install

Install through Homebrew:

```sh
brew install --cask lu-zhengda/tap/fold
```

If Homebrew asks you to trust this cask, run `brew trust --cask lu-zhengda/tap/fold` and repeat the install command. To upgrade through Homebrew, run `brew upgrade --cask --greedy lu-zhengda/tap/fold`.

Or download the disk image from [GitHub Releases](https://github.com/lu-zhengda/fold/releases/latest), open it, and drag Fold into Applications. The download includes Apple silicon and Intel builds. Fold supports the two most recent major versions of macOS.

## Build from source

With Xcode 26 or later installed, run the build script.

```sh
./script/build_and_run.sh
```

The script builds and opens `dist/Fold.app`. You can open the bundle directly on subsequent launches or move it to Applications.

## Use the shelf

- Copy something while Fold is running. On macOS versions that ask about pasteboard access, allow Fold to read the clipboard for continuous capture.
- Press **Control–Option–V** or click the stack icon in the menu bar to open the shelf.
- Use **↑** and **↓** or scroll through the history list. The preview follows your selection.
- Start typing to search, or press **Command–F**. Press **Space** on a selected clip for a larger preview. Search matches previews, source app names, and content types. Use **↑** and **↓** to browse search results.
- Double-click a clip or press **Return** to put it back on the clipboard and return to the previous app. Press **Command–V** there to paste.
- **Command–C** copies the selected clip and closes the shelf, including when automatic insertion is enabled.
- Right-click a clip and choose **Rename Clip…** to give it a searchable name. Clear the name to restore the original title.
- Press **Command–D** to add the selected clip to Favorites. Press it again to remove that clip from Favorites.
- Press **Delete (⌫)** or click the trash button to remove the selected clip from history and its pinboards. For file and folder clips, the originals stay in Finder.
- For one-step pasting, choose **••• → Enable Automatic Insertion** and grant Fold Accessibility access in System Settings. Fold will send Command–V to the previous app when you choose a clip.
- Right-click a clip and choose **Pinboards** to save it to Favorites or another board. Choose **••• → New Pinboard** to create a board. Use the **History** menu to switch boards.
- Press **Escape** to clear a search or close the shelf. Use the **•••** menu to pause capture, clear unpinned history, or quit.

## Settings

Open **••• → Settings…** on the shelf, or right-click the menu bar icon and choose **Settings…**.

- **Start at login** registers Fold with macOS. If approval is required, use the Login Items button in Settings.
- **Check for Updates…** checks the latest stable release immediately. If an update is available, you can review and install it.
- **Automatically install updates** lets Fold check periodically and install signed updates when it can safely restart. The switch is off by default. If you enabled only automatic checks in Fold 1.2.0, use **Check for Updates…** to check manually after upgrading.

## Local storage

Fold preserves supported pasteboard representations for text, rich text, web links, images, and Finder file references. File clips reference the originals. Fold uses its existing access when restoring them, including older clips. If macOS denies access to share an item, Fold asks you to select it and saves the grant for future copies. Color codes and common code snippets get distinct previews. Fold samples the system pasteboard about twice per second, so rapid successive copies can be missed.

History lives in `~/Library/Application Support/Fold/`. Fold keeps up to 500 unpinned clips within a 256 MiB payload budget, plus clips saved to pinboards. Copies over 20 MiB and items marked concealed, transient, or autogenerated are skipped. Other copied content, including unmarked sensitive text, can enter history. Local history files are readable by your macOS account.

## Verify

Run the same source checks as CI on a Mac with Xcode installed.

```sh
./script/verify.sh
```

The harness runs the Swift tests with coverage, builds a universal app using the release packaging code, and mounts the resulting DMG to check the app, signature, deployment targets, and Applications shortcut. CI also launches and quits the packaged app in a disposable GUI session and uploads `.build/verification/coverage.json`. To include that launch locally, use `./script/verify.sh --launch`. The app reads the clipboard while running.

To verify a published release, use a Mac with Xcode, GitHub CLI, and jq.

```sh
./script/verify-release.sh v1.0.0
```

Omit the version for the latest stable release. This downloads the public assets, checks the SHA-256, applies download quarantine, and checks both the image and embedded app against Fold’s Developer ID team, notarization tickets, and Gatekeeper. Each published stable release triggers this check.

After updating the tap, run **Actions → Verify published Fold → Run workflow** with the Homebrew option enabled. This also runs weekly for the latest release. The runner checks the current cask’s version, URL, digest, and app-only installation, installs it, and starts the installed executable to verify that it registers as a menu bar app. On a desktop Mac, open Fold from Applications to verify the first-launch experience in Finder. To reproduce that installation on a disposable Mac, run `./script/verify-release.sh --install-cask`. It installs Fold in Applications and leaves the Homebrew receipt available for inspection.

### Finder keyboard check

In Finder, copy a test folder containing a small file, then copy a different item. Open an empty destination folder. Press **Control–Option–V**, select the earlier folder with the arrow keys, press **Return**, and press **Command–V** in Finder. Open the resulting folder and verify the file contents. Repeat after relaunching Fold to exercise the saved file grant. An accessible folder should restore immediately. For a folder that requires permission, cancelling the picker should preserve the clipboard. This interactive check complements the automated file-reference tests.

## Release builds

Set the version and build number in `Resources/Info.plist`. Run `script/release.sh` with `SIGNING_IDENTITY` set to a Developer ID Application identity and `NOTARY_PROFILE` set to a notarytool keychain profile. The script builds both architectures, signs and notarizes the app and disk image, verifies their tickets with Gatekeeper, and writes the disk image, checksum, and Sparkle feed to `dist/`. Publish all three files together on the stable GitHub Release. Sparkle signs the update using the `local.fold.clipboard` EdDSA key in the release machine’s login Keychain. Keep a secure backup of that key for future releases.
